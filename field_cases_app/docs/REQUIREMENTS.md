# المتطلبات المعتمدة — المرجع الأساسي للمشروع

> هذا النص هو المرجع الأساسي المعتمد. أي فكرة جديدة تُضاف في قسم "إضافات لاحقة" أسفل الملف بتاريخها، بدل البدء من الصفر.

## الهدف
تطبيق جوال متكامل لإدخال الحالات الميدانية وحفظها محليًا على جهاز المستخدم، ثم تصدير الحالات منفردة أو على شكل دفعات، واستيرادها لاحقًا داخل نسخة أخرى من نفس التطبيق، مع نقل الصور والمرفقات وربطها تلقائيًا بالحالات.
تسهيل إدخال الحالات من الجوال، وتوحيد صياغتها، والاحتفاظ بها محليًا، ثم مشاركتها عبر وسائل المشاركة في الجوال مثل WhatsApp، مع تجميع الحالات الواردة داخل نسخة المشرف دون سيرفر خارجي أو خدمة سحابية.

## 1. المتطلبات الأساسية
- يعمل على iPhone وAndroid، ومناسب للاستخدام بيد واحدة قدر الإمكان.
- تقنية Cross Platform مناسبة مثل Flutter، مع بنية قابلة للتطوير والصيانة.
- يعمل بالكامل Offline.
- ممنوع: سيرفر خارجي، Firebase، Supabase، قواعد بيانات سحابية، تخزين سحابي تلقائي، Analytics خارجية، إرسال بيانات للمطور، Telemetry، أي API خارجي لنقل بيانات الحالات.
- جميع البيانات تبقى داخل الجهاز ما لم يقرر المستخدم تصديرها أو مشاركتها.

## 2. قاعدة البيانات المحلية
- SQLite أو حل محلي بنفس الاعتمادية، قاعدة مستقلة لكل جهاز، تعمل دون إنترنت.
- لا تُخزن الصور الكبيرة كـ BLOB إلا لسبب تقني قوي؛ الأفضل: البيانات في القاعدة، الصور في مساحة التطبيق المحلية، والمسار والعلاقة في القاعدة.

## 3. معرف الحالة
- UUID فريد تلقائي، وظاهر للمستخدم مثل `EVT-20260925-A72F91` مع الاحتفاظ بـ UUID الكامل داخليًا.
- يُستخدم في: منع التكرار، ربط الصور، الاستيراد، التصدير، معرفة حالة التعديل، تتبع النسخ المختلفة.

## 4. الشاشة الرئيسية
حالة جديدة — الحالات السابقة — البحث — التصدير — الاستيراد (للمشرف فقط) — الدفعات الواردة (للمشرف) — الإعدادات.
عربية بالكامل RTL، بسيطة جدًا ومناسبة للموظف الميداني.

## 5. إنشاء حالة جديدة
- نموذج ذكي متدرّج، لا يعرض كل الحقول دفعة واحدة؛ الحقول تتغير بحسب نوع الحالة.
- أنواع أولية قابلة للتعديل: جسم صلب، شظايا، طائرة مسيرة، حريق، حالة أمنية، حادث أمني، أخرى.

## 6. الحقول الأساسية
معرف الحالة، رقم تسلسلي ظاهر، نوع الحالة، التاريخ، الوقت، المحافظة، المركز أو الموقع، مصدر البلاغ، وصف الموقع، الإحداثيات، معلومات الحالة، الإجراء المتخذ، الجهات التي تمت مباشرتها، وجود إصابات (نعم/لا) وعددها، وجود وفيات، وجود أضرار ووصفها، ملاحظات، اسم/رمز المدخل، تاريخ إنشاء السجل، تاريخ آخر تعديل، حالة السجل، حالة التصدير، عدد الصور، المرفقات. بعضها يظهر بحسب النوع.

## 7. الإحداثيات
زر "التقاط الموقع الحالي" بعد موافقة المستخدم (مثال `24.468245, 39.612354`)، مع نسخ الإحداثية، فتحها على الخريطة، تعديلها يدويًا. لا يُرسل الموقع لأي سيرفر.

## 8. الصور والمرفقات
تصوير بالكاميرا، اختيار من المعرض، أكثر من صورة. تُخزن في مساحة التطبيق المحلية ومرتبطة بمعرف الحالة، بأسماء منظمة مثل `EVT-20260925-A72F91_001.jpg`. عرض الصور وحذف صورة قبل الاعتماد. لا رفع للإنترنت.

## 9. إنشاء النص التلقائي
الموظف يدخل البيانات الأساسية والتطبيق يصوغ النص. مثال:
> "عند الساعة 7:30 مساءً ورد بلاغ من العمليات الموحدة (911) عن العثور على جسم صلب جنوب مركز الرايس، وبالانتقال للموقع اتضح وجود أجزاء من جسم صلب تنبعث من أحدها نيران خفيفة، دون تسجيل إصابات، وجرى إبلاغ الدفاع المدني وإدارة الأسلحة والمتفجرات لإكمال اللازم كل فيما يخصه."

نظام Templates مرن يسمح بإضافة قوالب جديدة لكل نوع.

## 10. معاينة الحالة
تعرض النص النهائي والبيانات والإحداثيات والصور، مع: تعديل البيانات، تعديل النص، حفظ، مشاركة النص، مشاركة الحالة.

## 11. حالات السجل
مسودة، مكتملة، جاهزة للإرسال، تم تصديرها، تم تعديلها بعد التصدير، مستوردة، معتمدة. تعديل حالة مصدّرة يحوّلها تلقائيًا إلى "تم التعديل بعد التصدير".

## 12. الحالات السابقة
مرتبة من الأحدث للأقدم ومجمعة باليوم (الوقت، النوع، المحافظة، حالة التصدير)، والضغط يفتح الحالة.

## 13. البحث والتصفية
البحث برقم الحالة، النوع، التاريخ، المحافظة، الموقع، كلمة من الوصف، حالة التصدير، مصدر البلاغ. فلاتر: اليوم، هذا الأسبوع، غير المصدرة، المصدرة، المعدلة بعد التصدير.

## 14. المشاركة عبر WhatsApp
بدون WhatsApp Business API وبدون إرسال تلقائي. Share Sheet الخاص بالنظام، والمستخدم يختار التطبيق. زر "نسخ النص". الصور عبر نظام المشاركة.

## 15. التصدير
الحالة الحالية فقط — اختيار عدة حالات — جميع غير المصدرة — (مستقبلًا) فترة زمنية من/إلى.

## 16. حزمة التصدير
ليست Excel فقط؛ حزمة واحدة `.casepkg` (مثل `ينبع_20260925.casepkg`) تحتوي بيانات الحالات والصور والمرفقات وMetadata الدفعة، داخليًا Archive منظم: `manifest.json`, `cases.json`, `attachments/<case>/...`.

## 17. manifest.json
package_id، تاريخ ووقت الإنشاء، إصدار التطبيق، عدد الحالات والصور والمرفقات، معرف جهاز منطقي غير حساس، اسم/رمز الجهة، Hash/Checksum، إصدار صيغة الحزمة.

## 18. cases.json
بيانات الحالات بعلاقات واضحة بين case_id والبيانات والمرفقات والصور وتاريخ التعديل وحالة السجل. JSON هو المصدر الأساسي للاستيراد؛ Excel مستقبلًا للاطلاع فقط.

## 19. التشفير
دراسة تشفير الحزمة بحل قوي مثل AES-GCM (لا ZIP Password كحل رئيسي)، مع Key Management صحيح: لا مفتاح داخل الملف ولا يُرسل معه. يُشرح نموذج الحماية قبل التنفيذ.

## 20. الموظف والمشرف
نفس التطبيق والكود مع Role محلي.
- EMPLOYEE: إنشاء حالة، تعديل حالاته، الحالات السابقة، البحث، الصور، إنشاء النص، التصدير، المشاركة.
- SUPERVISOR: كل ما سبق + استيراد الدفعات، صندوق الوارد، معاينة الدفعات، اعتماد/رفض الحالات، تجميع الوارد، البحث في جميع الحالات، التصدير الشامل.

## 21. الاستيراد
زر "استيراد بيانات" يفتح File Picker لملف `.casepkg`، فحص قبل الإدخال، وعرض: اسم الدفعة، عدد الحالات والصور والمرفقات، الجديدة، الموجودة، التي لها نسخة أحدث، الأخطاء؛ ثم [معاينة] [اعتماد الاستيراد].

## 22. منع التكرار
لا يعتمد على اسم الملف بل على case_uuid. لا نسخ مكررة عند إعادة الاستيراد. عند وجود نسخة أحدث: "توجد نسخة أحدث من هذه الحالة" مع: مشاهدة الفروقات، الاحتفاظ بالحالية، الاستبدال، الاحتفاظ بالنسختين (Versioning).

## 23. صندوق الوارد
المستورد لا يدخل السجل النهائي مباشرة: واردة ← تحت المراجعة ← معتمدة. شاشة "الدفعات الواردة" (الجهة، عدد الحالات والصور، التاريخ)، وداخل الدفعة: تحديد الكل، إلغاء تحديد، معاينة، اعتماد الكل، اعتماد المحدد.

## 24. قاعدة بيانات المشرف
مستقلة في جواله، تستقبل من عدة موظفين/جهات، مع إجمالي اليوم وتصنيف حسب الجهة ونوع الحالة.

## 25. النسخ الاحتياطي
"إنشاء نسخة احتياطية" مشفرة (القاعدة، الصور، المرفقات، الإعدادات اللازمة)، بدون Cloud تلقائي، والمستخدم يحدد المكان. "استعادة نسخة احتياطية" مع تحذيرات واضحة.

## 26. حماية التطبيق
Face ID، Touch ID، Biometric على Android، PIN بديل لا يُخزن كنص واضح، وSecure Storage للمفاتيح والأسرار.

## 27. حماية الملفات
الملفات داخل مساحة التطبيق الخاصة، لا تظهر في المعرض العام إلا بتصدير المستخدم، ولا ملفات حساسة في مجلد عام.

## 28. الإعدادات
اسم الجهة، اسم/رمز المستخدم، أنواع الحالات، المحافظات، المراكز، مصادر البلاغ، الجهات المباشرة، قوالب الصياغة — قوائم قابلة للتعديل.

## 29. الأداء
سلاسة مع آلاف الحالات والصور: Pagination، Lazy Loading، Indexes، Thumbnails.

## 30. سلامة البيانات
Transactions في الاستيراد والحذف واعتماد الدفعة؛ إما استيراد كامل أو Rollback.

## 31. سجل العمليات
Audit Log محلي (خصوصًا للمشرف): التاريخ، الوقت، العملية، معرف السجل.

## 32. حذف البيانات
ليس بضغطة واحدة؛ تأكيد، Soft Delete أولًا، وشاشة "المحذوفات" للاستعادة أو الحذف النهائي.

## 33. الواجهة
عربية حديثة بسيطة RTL: Cards، أزرار كبيرة، نص واضح، قوائم منسدلة، Switch، Checkboxes، Bottom Navigation. غير مزدحمة، والأولوية للسرعة.

## 34. سير العمل
- الموظف: فتح ← حالة جديدة ← النوع ← المعلومات ← الموقع ← الصور ← النص تلقائيًا ← معاينة ← حفظ ← مشاركة عاجلة عند الحاجة. نهاية الفترة: التصدير ← غير المصدرة ← حزمة واحدة ← مشاركة الملف.
- المشرف: استلام الحزمة ← حفظها في Files ← استيراد ← اختيار الملف ← فحص ← معاينة ← اكتشاف المكرر ← اعتماد ← إدخال الحالات والصور.

## 35. قابلية التوسع (لا تُنفذ إلا عند الطلب)
تقارير إحصائية، لوحة مؤشرات، PDF، Excel، ربط مع برنامج Windows، قاعدة مركزية في شبكة داخلية، مزامنة LAN اختيارية، QR، AirDrop، Near Share، NFC، تصنيف ووسم الصور، طباعة تقرير الحالة، تقرير يومي تلقائي.

## 36. المطلوب قبل البرمجة
تحليل المتطلبات، Architecture، التقنية، بنية المشروع، تصميم القاعدة، ER نصي، الجداول والحقول، العلاقات، تخزين الصور، صيغة التصدير والاستيراد، منع التكرار، التشفير، إدارة المفاتيح، الصلاحيات، الشاشات، User Flow، خطة مرحلية ← (منجز في `DESIGN.md`).

## 38. قواعد البرمجة
كود قابل للصيانة، لا ملف واحد لكل شيء، فصل طبقات، أسماء واضحة، تعليقات عند الحاجة فقط، معالجة أخطاء واضحة دون تجاهل Exceptions، لا أسرار Hardcoded، لا API خارجي، لا اتصال بالإنترنت دون سبب، كل وظيفة قابلة للاختبار، لا تغيير لتصميم القاعدة دون توضيح، لا حذف لميزة معتمدة، ملفات كاملة أو Patch واضح لكل مرحلة، وتوافق الإصدارات القديمة من ملفات casepkg.

## النتيجة النهائية
تطبيق جوال آمن دون إنترنت: الموظف يسجل الحالات والصور ويحفظها ويصوغها ويشاركها ويصدرها في حزمة واحدة، والمشرف يستورد الحزمة في نفس التطبيق مع البيانات والصور دفعة واحدة، ومنع التكرار، والمراجعة والاعتماد — دون أي سيرفر خارجي.
